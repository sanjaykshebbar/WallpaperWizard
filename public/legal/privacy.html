Usage & Privacy Policy

Last updated: 5 July 2026

The short version

No telemetry. AdBoard collects no analytics, usage statistics, crash reports, or tracking of any kind. There is no “phone home” of any sort.
  • Your data stays on your infrastructure. Everything AdBoard stores lives in the backend you choose and control (your Supabase project, your Firebase project, or your own server's disk).
  • Hobby software, provided as-is. Built for fun and shared under the MIT License. Host it as you need, modify it as you need, improve it as you need. There is no warranty and no guaranteed support.

1 · What data AdBoard stores (in your backend)

DataPurposeWhere
Admin accounts (email, password hash or your auth provider's record, role)Sign-in and permissionsYour backend
Two-factor secrets (TOTP)Optional 2FAYour backend (never shown after enrollment)
Uploaded media and its settingsThe content your screens displayYour storage bucket / server disk
Display settingsKiosk behaviorYour backend
Viewer device records (random device ID, IP address, browser user-agent, last-seen)The “Display Viewers” list and per-device approvalYour backend
Audit log (who did what, when)Accountability for admin actionsYour backend
IP allowlist (if enabled)Optional dashboard access controlYour backend

Some preferences (theme, “tutorial seen”, session hints, the viewer device ID) are kept in the browser's localStorage on the device itself.

The operator of an AdBoard deployment — not the software's author — is the data controller for anything stored by their instance. If you deploy AdBoard for others (e.g., in a workplace), local privacy laws about IP addresses and audit records are your responsibility.

2 · External network connections (complete list)

  1. Your chosen backend (your Supabase / Firebase project or your own server) — all application data. Fully offline with the self-hosted Docker backend.
  2. Google Fonts (fonts.googleapis.com) — UI typefaces on page load. For a zero-external deployment, self-host the fonts and edit src/index.css.
  3. ipify (api.ipify.org) — contacted only on cloud hosting and only when a feature needs this device's public IP (IP-restriction gate, viewer registration). The self-hosted backend never calls it.
  4. GitHub — contacted only when a user explicitly submits the in-app feedback form (Beta), to create an issue on the project repository.

That's the whole list. No analytics providers, no ad networks, no telemetry endpoints, no update checks.

3 · Cookies & local storage

AdBoard sets no tracking cookies. Authentication state is handled by your chosen auth provider (e.g., Supabase session tokens) and by localStorage entries scoped to your deployment's domain. Clearing site data removes them.
